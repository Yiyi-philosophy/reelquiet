## Problem Statement

用户把任务交给 Claude Code 后，要等几十秒到几分钟。这段时间要么盯着 spinner 发呆，要么切去别的窗口，然后错过权限确认。现有的"等待小游戏"mod 不是用街机游戏抢注意力（cc-arcade、claude-games），就是用 token 消耗喂宠物（AgentPet）。

Claude Fish 要把这段等待变成一件**安静、真实、能留下来**的事：鱼塘跟着 Claude 的真实工作节奏运转，平时不打扰；只在稀有鱼咬钩的瞬间请你按一下；每条鱼都记下你那一刻在做什么。

**主要设计对象是"留在终端里等"的用户。** 切去别的窗口的用户也能正常收获普通鱼和目击记录，但稀有鱼的心跳时刻主要为留在终端的人设计（见决策 D-OFFWIN）。

## What Makes This Cool

- **每条鱼都是一段工作记忆**：物种是真实的，"哪天、哪个项目、Claude 在干什么时上钩"是你自己的故事。FishDex 会慢慢变成编程日记。
- **真实生物学驱动玩法**：等得越久钓得越深（真实的海洋深度分层），夜间出现夜行性鱼，每个仓库被分配一片真实的"家乡水域"。冷知识本身就值得转发。
- **奖励推进，不奖励烧 token**：测试由红转绿、提交、任务完成会给鱼饵；token 消耗不给任何奖励。整个过程零 token 成本。
- **权限清单可以公开验证**：README 贴出 `claude plugin validate` 的完整输出和逐项说明；没有 `http`、`process`、`model` 调用。

## Constraints

- Claude Code 需要 v2.1.287 以上（本机为 2.1.292）。
- **宿主支持矩阵**（README 和 marketplace 描述里都要写）：
  - 终端 `claude`：完整支持。
  - Desktop Code 标签：v0.1 只显示一行文字横条（没有 Raster），稀有档按 D-DESKTOP 处理。
  - VS Code 聊天面板、`claude -p`、云端会话：**整个游戏自动停用，运行时完全静默**。不抛竿、不记录、不注册命令、不输出任何内容。这些宿主不支持的情况只在 README 和 marketplace 描述里说明。原因是这些环境里唯一能显示文字的办法是返回 `{ text }`，那会写进 Claude 的上下文。
  - 判断方式：在 `session.start` 读 `$.session.surfaces()`，渲染时再看 `e.surface`。
- Mod 读不到键盘。唯一不需要切换焦点的输入方式是：横条上的数字热键按钮，在**空提示框**里单独输入该数字时触发。另外可以用 `action` 绑定一个组合键，但用户需要先自己配置。
- 重绘上限：可见的横条或面板最多 30 fps。面板分两档：mod 自己弹出需要终端 **≥144 列**；用户手动打开过一次之后降到 **≥110 列**。
- `$.store`：文档说明它是"本插件自己的 JSON 文件，放在 `~/.claude/plugins/store/` 下"，所以 4 MiB 的上限**按插件计算**（由 OQ9 确认）。所有会话共享，读写不是原子操作，支持 `keys()` 列出全部键，超过 `cleanupPeriodDays` 没有读写会被清理。
- 单个 hook 最多执行 10 秒，**`next` 内部的等待不计入**。T1 实测：权限确认等待 23.6 秒，hook 没有被跳过。模块里没有 Node API，也没有 `setTimeout`；定时用 `$.clock`，动画用 `$.ui.blit`。

## Premises（已确认）

1. **默认安静，只在关键时刻需要你。** 普通鱼和少见鱼自动收杆。**稀有鱼和传说鱼**必须主动收杆；错过了会逃走，但记为"目击"。遇到权限确认、Claude 提问时，咬钩状态冻结。
2. **核心身份是"真实物种 + 每次捕获都是工作日记"。** 钓鱼只是载体。做取舍时，优先保护图鉴和日记的长期价值。
3. **权限面最小，并且可以公开验证。** Git 进度**只**通过读 reflog 文件获取，不执行 `git` 命令，也不从工具调用结果里推断。
4. **发布前必须改名，并加上"非官方"免责声明。**
5. **v0.1 只做 GIF 里的核心循环。** 游戏核心写成和 Claude Code 无关的纯逻辑，但不提前写 Codex 适配层。

## Decisions made in this session

| ID | 决策 | 理由 |
|---|---|---|
| D-SPECIES | **只用真实物种**（真实名称、分类、栖息深度、昼夜习性、体长分布） | 不会过时，符合 geek 对真实性的偏好；深水、夜间、仓库生态都有生物学依据。编程梗风格的鱼已否决：容易显得刻意卖萌，看多了会腻，中英文谐音也没法互译。用户明确要求不做混合方案 |
| D-MEMORY | **工作记忆记在每次捕获上，不写进物种名** | 物种是图鉴的内容，捕获记录是用户自己的故事 |
| D-RARITY | **稀有度分四档：common、uncommon、rare、legendary。** 下文用 **"稀有档"（`tier ≥ rare`）** 统一指 rare 和 legendary，"高价值"不再单独作为一个维度。体长是否打破个人纪录在收杆时判定，不影响要不要主动收杆 | 统一说法：状态机、schema 和所有规则都只认 `tier ≥ rare` 这一个判定条件 |
| D-REEL | **只有稀有档需要主动收杆；** 其他档在咬钩后自动收杆 | 保留心跳时刻，又不打扰日常工作 |
| D-SIGHT | **错过的稀有档记为目击**（图鉴区分"见过"和"抓到"） | 保留错过的代价，同时把遗憾变成一个故事 |
| D-DRAFT | **前置条件：OQ1 的验证结果。** 能检测到提示框有草稿时，稀有档咬钩的倒计时暂停，横条提示"发送或清空输入后按 1"。检测不到时，走 D-FALLBACK | Codex 冷读指出：数字热键在有草稿时失效，会惩罚"提前输入下一条指令"这个好习惯 |
| D-FALLBACK | **检测不到草稿时：** 稀有档的咬钩窗口加长到 20 秒；第一次出现稀有档咬钩时，用 toast 引导用户绑定组合键。没绑定的话，打字期间错过的稀有档记为目击，**这个代价我们接受** | 保持零配置也能用。代价是可以接受的，因为错过只会变成一条目击记录 |
| D-CARRY | **回合结束时，如果有稀有档正在咬钩：** 进入 `carried` 状态，倒计时清除、定时器取消，横条只显示一张静态提示"稀有鱼还挂着，按 1 收杆"。能检测到草稿且提示框有内容时，提示改为"清空输入后按 1，或用组合键"。用户提交下一条 prompt 时还没收杆，就结算为目击。**实际能收杆的时间窗口是"回合结束"到"开始打字"之间**，在这之外错过，代价和 D-FALLBACK 一样，我们接受 | 回合结束正是用户回到终端、提示框为空的时刻，是收杆的最好时机。静态提示不抢注意力。这条也照顾了切去别的窗口的用户 |
| D-ABORT | **用户中断（`isAborted: true`）时：** 不发任何奖励或鱼饵；钩上的普通鱼直接逃走、不留记录；钩上的稀有档记为目击；清除冻结标志 | 堵住"发起任务后立刻中断"的刷奖路径 |
| D-OFFWIN | **离开终端时，不提供任何系统级通知通道。** 要发系统通知就需要 `process`，会破坏权限承诺。可以选择开启音效（`$.audio`，默认关闭），第一次出现稀有档咬钩时用 toast 告知可以开启 | 刻意的取舍：心跳时刻只为留在终端的用户设计；离开的用户靠 D-CARRY 兜底 |
| D-HOTKEY | **收杆按钮（`hotkey:'1'`）只在"状态为 `hooked(tier ≥ rare)` 或 `carried`，并且没有冻结"时渲染。** 其他时候，包括冻结期间、AskUserQuestion 期间、空闲时都不渲染 | 不渲染按钮时，数字 `1` 照常进入提示框，不会吞掉用户正常输入的 "1" |
| D-DESKTOP | **Desktop App（文字横条）上，稀有档也自动收杆，但不计稀有加成，也不产生目击。** 横条上只显示文字结果 | 数字热键在 Desktop 横条上是否生效还没验证（OQ8），所以不让 Desktop 用户遇到无法完成的心跳时刻 |
| D-GIF | **v0.1 的 GIF 讲完整核心循环**：Task → Auto Cast → Agent Working → Bite → One-key Reel → Catch Card → Task Complete | 15 秒只讲一个故事。允许轻微的深浅水色变化；不加天气突变，不展示完整 FishDex |
| D-LONGTERM | **长期方向**：工作记忆、Agent 状态映射为天气、可分享的捕获卡片、项目野外日志（Codex 提出）、水族箱 | 来自 D1。"和 Claude 并肩钓鱼"暂缓。**水族箱移出阶段 2** |

## Cross-Model Perspective

由 Codex（gpt-6-astra，high reasoning）在只看结构化摘要、没看过对话的情况下独立给出意见，要点如下：

- **最酷的版本**：一本伪装成鱼塘的"项目野外日志"。真实鱼种按仓库生态出现，测试失败打开深水区，测试转绿和提交让鱼群往上游迁徙，完成的任务变成产卵事件。`/fish log` 生成一条可分享的项目推进时间线。
- **用户最兴奋的点**：用户说"鼓励耐心、良好的开发习惯，以及已完成的任务数量，即以项目推进进度优先，而非 token 的消耗"。钓鱼只是外壳，真正的产品是一个奖励健康、持续工程习惯的安静视觉系统。
- **能完成一半工作的现有项目**：官方样例 [token-weather](https://github.com/anthropics/claude-code-playground/tree/main/claude-code/mods/token-weather)。剩下要自己做的：纯逻辑游戏核心、事件适配、鱼表、暂停处理、存档、捕获卡片、确定性测试。
- **对前提的挑战**：Codex 认为"稀有鱼必须主动按键"是错的，因为数字热键在提示框有草稿时失效，会让奖励取决于提示框里有没有字，而不是用户有没有在留意。它的方案是"所有鱼都自动收杆，按键只是升级这次捕获或额外给加成"。按这个方案，没按键时**鱼照样到手，只是少了加成**。
- **综合结论**：认同周末切片的做法，也认同以 token-weather 为参考。挑战点本身成立。不采纳它的方案，是因为没按键的代价只是少一点加成，咬钩那一刻就没有心跳感了。而用户明确要求"对于一些高价值或稀有的鱼类，需要用户主动点击操作"。最后的处理是：保留主动收杆，把"打字时失效"的问题用 D-DRAFT、D-FALLBACK、D-CARRY 来修。"项目野外日志"记入长期方向。

## Approaches Considered

- **A 周末垂直切片**：最快，但物种写死在代码里、分层不清楚，发布前大概率要重构。
- **B 三层架构 + 物种一次到位**：否决的原因是**顺序**，而不是总工作量：在验证"好不好玩"之前，就要先投入物种调研和面板开发。
- **C 先切片，再长成架构**（选定）：见下一节。阶段 2 的物种内容单独作为一条工作流并行推进。

## Recommended Approach

**方案 C：先做切片，再在同一套结构上长成完整架构。**

### 阶段 1：可以录 GIF 的垂直切片（human 约 1 周 / CC 约 1 天）

```
claude-fish/
├── .claude-plugin/plugin.json
├── hooks/hooks.json            # modules: ["./register.ts"]
├── hooks/register.ts           # 入口：只调用 on(...)，把事件转交给 src/adapter
├── src/adapter/                # 唯一可以使用 $ 的业务代码
│   ├── events.ts               # Claude Code 事件 → 游戏事件、定时器、渲染调度
│   ├── git.ts                  # reflog 读取（fs.* 只能出现在这里和 export.ts）
│   └── export.ts               # /fish export（阶段 2）
├── src/core/                   # 纯逻辑，不依赖 $，可以单独测试
│   ├── pond.ts                 # 状态机（见下）
│   ├── clock.ts                # 只接收 now 参数推进状态，自己不读系统时间
│   ├── rng.ts                  # 带种子的随机数，保证测试结果确定
│   ├── loot.ts                 # 按深度、时间、水域、鱼饵抽取物种
│   ├── signals.ts              # 测试命令识别、红转绿判断
│   └── memory.ts               # 零 token 的工作记忆模板
├── src/store/                  # $.store 的键空间与折叠逻辑（见"存储"一节）
├── src/render/band.ts          # 横条 Raster，加上按条件渲染的收杆 Button
├── src/render/card.ts          # ASCII 捕获卡片
├── data/species.json           # schema 定稿，v0.1 只放 1 种 common + 1 种 rare
├── types/index.d.ts            # PluginState
└── tests/*.test.ts             # claude plugin test
```

**状态机**（`pond.ts`）：

```
idle ──cast──▶ waiting ──bite──▶ hooked(tier, deadline)
                 │                   │  tier < rare：立即进入 caught
                 │                   │  tier ≥ rare：等待 reel，超时进入 escaped→sighting
  complete：waiting → idle（结算）；hooked(tier ≥ rare) → carried（D-CARRY）
  carried：没有 deadline，不会超时；定时器取消，只做静态渲染
           reel → caught；下一次 cast → 先结算为 sighting，再开始新的一竿
  abort（isAborted）：按 D-ABORT 处理 → idle
  reset（clear/resume/fork）：钩上的稀有档 → sighting → idle

  标志位（可以叠加在 waiting / hooked 上）：
    frozen：模拟时间停止（倒计时不走、深度不涨），收杆按钮隐藏，动画暂停
      置位：见事件映射里的 freeze
      清除：unfreeze、turn.start（强制清除）、complete、abort、reset
      兜底：turn.start 无条件清除，所以即使 unfreeze 漏判（OQ6），
            最晚到下一竿也能恢复，不会卡死
    draftPause（D-DRAFT）：只暂停稀有档的倒计时，按钮保留
```

**时间推进**：只在 `waiting` 和 `hooked` 状态下启动 `$.clock.every(100)`，也就是每秒 10 次，进入 `idle` 或 `carried` 时取消。每次触发都做两件事：按真实流逝时间推进模拟（深度、咬钩概率、倒计时），然后用 `$.ui.blit` 只重绘横条上的 Raster。**模拟和动画都是 10 fps**，低于 30 fps 的上限。工具调用只用来产生 signal，**不负责推进时间**。这样即使 Claude 长时间纯推理、没有工具调用，鱼塘也照常运转。

**事件映射**（只算主代理：`e.agentId` 为空的事件）：

| Claude Code 事件 | 游戏事件 |
|---|---|
| `turn.start` | 强制清除冻结；如果当前是 carried，先把它结算为目击；然后 `cast` |
| `tool.call`，在 `await next(e)` 之后 | `signal`：测试命令由红转绿。**不负责推进时间，也不判断 git 提交** |
| `tool.check` 的结果为 `ask`；`classic.Notification` 的 `permission_prompt` 或 `elicitation_dialog`；`ui.render` 渲染了 `AskUserQuestion` | `freeze` |
| 冻结期间又出现一次 `tool.call` 或 `turn.step` | `unfreeze`：说明权限已处理、turn 继续了 |
| `turn.complete` 且 `isAborted: false` | `complete`：结算和发奖，读一次 reflog |
| `turn.complete` 且 `isAborted: true` | `abort` |
| `classic.SessionStart`，来源为 clear、resume 或 fork | `reset`：钩上的稀有档记为目击，清除冻结，回到 idle |

**子代理**（`e.agentId` 不为空）的事件：
- 不触发 `cast` 和 `complete`。
- 它的 `tool.call` **也会**产生"测试由红转绿"的 signal（同一个会话内去重）。
- 它触发的权限确认**也会**冻结鱼塘。
- 主 turn 结束后，后台子代理还在跑时，鱼塘保持 idle。

**测试命令识别**（`signals.ts`）：
- 内置正则清单：`npm|pnpm|yarn|bun test`、`npx (jest|vitest)`、`pytest`、`cargo test`、`go test`、`mvn test`、`gradle test`、`make test`、`rspec`、`phpunit`、`dotnet test`。用户可以通过 `userConfig.testCommands` 追加自定义正则。
- 判定结果：`isError` 为真或退出码非零算红（OQ4 会确认能不能拿到退出码）。
- 记忆方式：以"会话 ID + 规整后的命令指纹"为键记住红灯。之后同一个指纹变绿，触发**一次** signal，然后清除红灯。会话结束时全部清空。

**运行时状态存放**：
- 鱼塘状态放在 `$.state` 里，热重载后不会丢。
- 定时器在 `session.start` 时根据 `$.state` 重新建立。
- `/clear`、`/resume`、`/branch` 按上面映射表里的 `reset` 处理。

### 存储（阶段 1 就定好键空间，阶段 2 扩充）

- **原则上只追加、不修改**：所有可变数据都写成不可变的事件键，例如 `c:<sessionId>:<seq>` 表示一次捕获，`s:` 表示目击，`g:` 表示获得奖励。不同会话写的是不同的键，所以平时不会出现写竞争。**唯一的例外是下面的"压缩"**。
- **索引键（折叠缓存）**：每个会话额外维护自己的 `i:<date>:<sessionId>`，内容是当天的计数，比如各类奖励发了几次、各物种钓了几条。这个键**只有本会话会写**，所以没有竞争。
  - 发奖时判断每日上限：只需要读当天所有会话的 `i:` 键（一般只有几个）求和，**不用扫描全部记录**。两个会话几乎同时发奖时，可能超发一次，这个误差可以接受，会写进文档。
  - 图鉴统计：读 `i:` 键汇总，再加上一个按会话分开写的物种首捕键 `d:<species>:<sessionId>`。
  - 只有 `/fish dex` 的明细页和 `/fish export` 才会用 `keys()` 做全量扫描（扫描耗时由 OQ9 测量）。
- **鱼饵只在本会话内有效**：在哪个会话获得，就只能在那个会话的鱼塘里用，会话结束后失效。这样鱼饵库存不需要跨会话同步。
- **容量预算**：一条捕获记录大约 300 B，按插件独占 4 MiB 计算，大约能存 10,000 条。
  - **详细记录上限设为 8,000 条**。超出后，把最旧的 common 和 uncommon 记录压缩成"物种 × 天"的汇总。
  - 稀有档、个人纪录、目击记录**永远不压缩**。
- **压缩的执行方式**：
  - **只在 `session.start` 里触发**。先抢占一个租约键 `lock:compact`，里面写上会话 ID 和 60 秒后的过期时间；只有租约没被别人持有、或者已经过期，才能抢到。
  - 每次最多处理 500 条，保证在 10 秒的 hook 预算内完成。
  - 顺序是**先写汇总键，再删除原始键**。汇总键名里包含被压缩那批原始键的哈希，所以即使删除到一半失败、下次重试，也不会重复汇总。读取时，已经被汇总覆盖的原始键会被忽略。
- **写入失败或接近上限**：立即触发一次压缩并重试。还是失败的话，只保留稀有档的写入，并用一次 toast 提示用户执行 `/fish export`。
- **防止被清理**：每次 `session.start` 都读一次 `$.store`，这样就会刷新清理计时。README 里会说明：如果超过 `cleanupPeriodDays` 天都不用 Claude Code，记录可能被清理，建议定期导出。
- **导出**：在阶段 2 实现 `/fish export`。由用户主动触发，写到**当前工作目录**下的 `fishdex-export-<date>.json`。相对路径按会话工作目录解析，所以不需要家目录，也不需要 `env`。执行后用 `$.ui.log` 提示文件路径，并建议加进 `.gitignore`。这是唯一一处 `fs.write`。

### 阶段 2a：代码（human 约 2 周 / CC 约 2 天）

- 宽屏时显示右侧面板，内容为图鉴和目击记录。用 `/fish` 打开或关闭面板。终端宽度 ≥144 列且用户从没打开过时，用一次 toast 引导："终端够宽，输入 /fish 打开鱼塘"。
- 仓库名哈希后映射到一片真实水域。
- 奖励信号的**初始参数**（阶段 2 开工时再调整，见 OQ10）：

  | 信号 | 奖励 | 递减规则 | 每日上限 |
  |---|---|---|---|

  | 测试由红转绿 | 1 个金色鱼饵 | 当天第 4 次起减半 | 5 |

### D9：遭遇模型（Sparse Active Encounters）
State: approved
Actual answer: C) Sparse Active Encounters（用户自定义选项，包含了 A 的规则，并增加了频率和防刷约束）
Accepted scope:
- ReelQuiet 的目标是让打扰**极低频、高价值**，而不是做到零打扰。common 和大部分普通捕获不需要用户操作；rare 及以上有一个有限的主动收杆窗口，超时就逃走，并写入一条 sighting（D-SIGHT、D-CARRY 不变）。
- **频率目标**：正常一天编程下来，真正需要用户注意的稀有遭遇大约 0 到 2 次。
- **防刷**：稀有遭遇由三者共同决定：①有效的编程上下文，即主代理的回合正在进行，并且回合内有工具调用或模型请求；②遭遇预算；③随机数。单纯挂机、开多个会话、频繁刷新都不能稳定刷出稀有鱼。
- **阶段 1 的实现约束**：
  - 概率、窗口长度、每日预算都放在 `src/core` 的一个参数对象里，默认值写在代码里、可以调整；实际数值等用一段时间后再定（并入 OQ10）。
  - 预算以**全局、按天**计算：每次出现稀有遭遇，就只追加写入一条 `v1:e:<date>:<sessionId>:<seq>`。判断预算时，用 `keys()` 统计当天以 `v1:e:<date>:` 开头的键有几条。因为没有 CAS，**并发会话越多，可能超出的次数越多，没有确定上界**（O4）；这是一个"软预算"，不做保证，也不靠加锁来解决（与 D1 一致）。
  - `keys()` 的耗时由探针测量；如果太慢，先把当天的计数缓存在会话内存里，只在 `turn.start` 时刷新一次。
- **声音中立**：开启声音只会提高用户注意到咬钩的机会，不改变遭遇概率、稀有度和收杆规则。Sound UX Contract 中"忽略声音不得导致鱼丢失"一句改为："声音只是提醒，开启或忽略声音都不会让结果比静音时更差，也不会阻塞 Agent。"

**O1：.catch 返回 undefined 会改变工具结果（事实修正，P1）**

### R3-1 — consistency

**Problem**

> 压缩的触发点自相矛盾。「压缩的执行方式」写明「只在 `session.start` 里触发」，并为此配了租约键、单次 500 条上限和 10 秒预算；但紧接着的「写入失败或接近上限」又规定「立即触发一次压缩并重试」——那是在任意事件里（发奖、捕获写入）执行压缩，既绕过了 session.start 这个唯一入口和租约，也没有说明它是否同样受 500 条上限与 hook 预算约束。

**Remedy**

> 二选一并写清：要么允许写入失败路径即时压缩，并明确它也要抢租约、受同样的条数上限、失败时的行为；要么规定写入失败只做「标记待压缩」，真正的压缩仍然留到下一次 `session.start`。

**Problem**

### R3-3 — feasibility

**Problem**

> 租约键无法提供互斥。Constraints 自己写明 `$.store`「读写不是原子操作」，而抢占 `lock:compact` 正是读-改-写，两个会话几乎同时 `session.start` 时可能都认为拿到了租约。此时 A 已删掉一部分原始键，B 重新选批次得到的键集合不同、哈希也不同，于是写出两个互相重叠的汇总键，重叠部分在图鉴统计里被重复计数——现有的「汇总键名含批次哈希」只能防同一批次重复写，防不住重叠批次。Success Criteria 只写「租约冲突…测试通过」，没有定义冲突时的正确行为。

**Remedy**

> 定义能容忍租约争抢失败的幂等规则：批次按确定性顺序取整块（例如按序号区间而不是「当前最旧 500 条」）、汇总键按区间命名、读取折叠时对覆盖区间取并集去重；并写明抢不到租约的一方直接放弃本次压缩。

### R3-4 — completeness

**Problem**

> 汇总键的内容未定义。压缩「先写汇总键，再删除原始键」，并称「读取时，已经被汇总覆盖的原始键会被忽略」，但汇总键名里只有一个哈希，读取方无从知道哪些原始键已被覆盖；删除中途失败时留下的原始键会和汇总记录同时被计入，正是这条规则想避免的重复。

### R3-6 — feasibility

**Problem**

> 容量预算只覆盖可压缩的捕获记录。4 MiB / 8,000 条的预算只算了捕获记录，而键空间里的 `i:<date>:<sessionId>`（每天每会话一个）和 `d:<species>:<sessionId>`（每会话每物种一个）只增不减、从不压缩，长期使用后数量可能超过捕获记录本身；压缩又只处理 common 和 uncommon，稀有档、个人纪录、目击记录「永远不压缩」。一旦不可压缩的数据接近上限，「立即触发一次压缩并重试」没有任何可回收对象，而降级路径「只保留稀有档的写入」恰好还在写最不可压缩的那一类。

**Remedy**

### R3-7 — feasibility

**Problem**

> 阶段 2a 奖励表里的「改动极小的提交不计」在已承诺的权限面内无法实现。Premise 3 规定 Git 进度「只通过读 reflog 文件获取，不执行 `git` 命令」，权限清单也把 `fs.read` 限定在 `<repo>/.git` 与 `<gitdir>/logs/HEAD`；reflog 行只含提交 hash、动作类型和消息，不含改动行数或文件数，判断改动大小必须读 git object/packfile 或执行 `git`，两者都会越过清单并触发自家 CI。

**Remedy**

> 删掉这条递减规则，或换成 reflog 可得的信号（提交 hash 去重、单位时间内提交数递减、同一 hash 的 amend 不重复计），并同步修正奖励表与权限清单的说明。

### R3-8 — clarity

**Problem**

> 「稀有加成」从未定义。D-DESKTOP 用「不计稀有加成」作为 Desktop 降级的代价，但文档没有任何地方说明主动收杆相比自动收杆到底多给什么（额外鱼饵？图鉴标记？捕获卡片差异？体长加成？），也没说明 Desktop 上自动收到的稀有鱼在图鉴里算不算「抓到」、能否打破个人纪录。用户无法判断这个代价是否可接受，工程评审也无法实现。

**Remedy**

> 定义主动收杆的具体加成（给出字段名或数值），并写明 Desktop 自动收杆所得记录在图鉴、个人纪录和捕获卡片里的呈现方式。

### R3-9 — completeness

**Problem**

> Desktop 降级形态的渲染与时间推进未定义。宿主矩阵说 Desktop 标签「只显示一行文字横条（没有 Raster）」，而「时间推进」一节唯一的重绘手段是「用 `$.ui.blit` 只重绘横条上的 Raster」。Desktop 上这行文字横条靠什么刷新、10 Hz 的 `$.clock.every(100)` 是否照常运行并每秒重渲染 10 次文字、30 fps 上限如何适用，都没有写。

**Remedy**

> 规定 Desktop 的渲染通道与刷新频率（例如改用整段 `ui.render` 重渲染并把频率降到每秒 1–2 次，或只在状态变化时渲染），并在 Success Criteria 里加一条 Desktop 横条刷新的验收项。

### R3-10 — completeness

**Problem**

> 一次性标记与用户偏好没有存放位置和配置通道。键空间只定义了 `c:`/`s:`/`g:`/`i:`/`d:`/`lock:compact`，但文档依赖三处跨会话持久化的状态：「第一次出现稀有档咬钩」的组合键引导 toast（D-FALLBACK）、「可以开启音效」的首次 toast（D-OFFWIN）、「用户手动打开过一次之后降到 ≥110 列」的面板标记。音效开关本身怎么开（`userConfig` 字段？`/fish` 子命令？）也没有写，而权限清单的 `userConfig` 行只列了 `testCommands`，CI 又会对「表外的调用」报错。

**Remedy**

> 在键空间里加上偏好与一次性标记键（例如 `p:<name>`）并说明它们不参与压缩，指定音效开关的配置方式，并把它补进权限清单的 `userConfig` 行。

### R3-11 — consistency

**Problem**

**Remedy**

### R3-12 — clarity

**Remedy**

### R3-13 — completeness

### 视觉契约（已批准）

| ID | 规则 | 来源 |
|---|---|---|
| V-MONO | **单色优先。** 状态和稀有度必须完全由文字和字形表达，颜色只做增强，不承载任何独有信息。语义优先级：状态文案 > 稀有度标签 > 字形变化 > 颜色。`!` 表示咬钩或需要注意。鱼的长度只是装饰，不能作为唯一或主要的稀有度信号。 | D2（1A） |

| V-AMBIENT | 等待时最多显示 2 条通用鱼影，不带物种或稀有度含义，只是装饰。静态纯文本版本本身必须完整。鱼影每 2–4 秒移动一格，位置由会话种子决定，可复现。窄屏时优先去掉鱼影；冻结时停止移动；一旦咬钩就隐藏鱼影。鱼影不参与任何游戏逻辑。 | D3（2A） |
| V-RESULT | caught 或 sighted 的结果有最短显示时间：common/uncommon 3 秒，rare 及以上 6 秒，期间不会被下一竿覆盖。之后一直显示到下一竿开始，满 60 秒后变暗。不弹 toast。只有 rare 及以上的结果会写入 transcript，每个事件只写一组。 | D4（3A） |
| V-CARD | Catch Card 是 3 行、没有边框的 `$.ui.log`，只在 rare 及以上的 caught 时输出一次。sighted 只输出 1 行。内容只取 PublicCatchCard 的白名单字段，外加公开的学名。如果实测发现这 3 行会被其他消息打断，就降级为单行。 | D6（4bA） |

**探针结论（NO_COLOR，2026-10-08）**：设置 `NO_COLOR=1` 时，宿主会去掉 mod 里 `Text` 的颜色，但**不会去掉 `Raster` 单元格的前景色和背景色**（实测 `38;5;214` 和 `48;5;235` 仍然输出）。所以按 V-COLOR 的规定：只读取 `$.env.get("NO_COLOR")`，只用它来决定 Raster 是否改用默认色 `0x01000000`；`Text` 的颜色交给宿主处理。权限清单把 env 那一行改为"只读 `NO_COLOR` 这一个变量名，读取失败按单色处理"，README 中删掉"完全不访问 env"的说法。
